## 启用

2026-10-06 严格安全复查已补强扫码地址、官方通知／查单及精确金额匹配，见 [安全复查报告](ALIPAY_SECURITY_REVIEW.md)。通知校验加固覆盖官方支付宝各支付模式，实际手机发起流程不变。

1. 发布前核验本次代码提交的 Linux CI、unit／integration、安全及 GHCR 构建。前后端同版，无数据库迁移；本轮源码尚未发布，没有可交付的新固定镜像标签，不能用历史镜像代替。
2. 用户备份并部署后，后台“系统设置 → 支付设置”开启“电脑端支付宝使用手机网站支付扫码”并保存。默认关闭；`ALIPAY_DESKTOP_WAP_QRCODE` 存于原设置库，不新增 `.env` 参数。
3. 可见支付宝通道应选已配置手机网站支付的官方支付宝实例，商户签名及原通知地址须有效。聚合支付及其他通道不受此开关影响。
4. 创建新的电脑订单验证二维码。关闭开关只影响新订单，已有二维码按保存的订单模式和期限继续校验。

本站短链接的 origin 复用已校验的回跳地址；部署的手机网络必须可访问该站点 `/api/v1/payment/public/alipay/wap/:id`。该 GET 使用二维码内32字节随机令牌授权，不需要本站登录，不展示中间按钮。令牌不匹配返回404，过期／取消／已支付返回410和明确提示；正常情况只允许跳到保存的官方 `https://openapi.alipay.com/gateway.do` WAP 地址。订单期限向下对齐分钟，支付宝 `time_expire` 用东八区同一期限，电脑倒计时沿用同一 `expires_at`。

## 真机验收

新扫码模式要求本站 HTTPS（仅本机回环开发允许 HTTP）。建议先设置管理员“前端 URL”为实际 HTTPS 站点；已配置时仅接受此域名，未配置时依赖请求 Host，反代必须拒绝非本站 Host，不使用客户端 Referer 扩大白名单。正常跳转正文为空，失败及限流响应也禁止缓存。

- 用电脑分别创建余额充值与订阅订单，用支付宝 App“扫一扫”。确认无需登录本站或再次发起支付，进入预期商户与正确金额的支付宝付款界面。扫码界面与商户实际接受情况尚未验证。
- 刷新电脑付款页，确认同一订单仍显示二维码和倒计时；过期和取消后的二维码应提示失效，错误令牌／令牌改成其他订单 ID 应拒绝，已付码不再进入收银台。
- 手机浏览器创建新订单，核验原支付流程；关闭开关创建电脑订单，核验原桌面流程，已生成的旧扫码订单保持原模式。
- 用户确认后做一笔小额实付：电脑无需手动再次发起支付即可显示成功，核对支付订单与余额／订阅仅处理一次。付款确认来自原验签通知或交易查询，不以前台回跳成功作为入账证据。
- 若失败，记录去敏后的时间、订单 ID、支付宝错误码及电脑状态。不要把完整签名付款 URL、扫码令牌、私钥或通知签名贴入日志／截图；部署代理日志也应去除扫码 query，禁止记录完整 `Location` 付款地址。接口已发送 no-store／no-referrer，应用请求日志只记录 path。
