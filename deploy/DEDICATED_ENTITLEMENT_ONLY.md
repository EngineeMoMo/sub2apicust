# 包号当前职责与升级说明（2026-10-10）

本文件记录用户最新要求：**包号只负责账号归属、有效期和免扣，通用请求限制交给 sub2api。** 覆盖 DEDICATED_BILLING_PLAN.md 中历史共享限额方案。当前仅源码完成，未提交推送或部署。

## 保留的职责

- 校验当前成员、所属专属分组、实际选中账号、有效期与撤销状态；保持账号隔离，不能回退借用公共池或其他账号。
- 管理多人归属、续期、撤销、移除成员和逻辑删除；移除成员同步撤销对应分组权限并停用相关Key。移除100人硬上限，仍要求成员非空、ID有效且不重复。
- 有效包号的获准专属组请求不要求用户余额，结算不扣客户余额或订阅额度。普通组维持原计费。
- 保留Token、参考金额、包号计费类型和结算去重；已获准请求的异步结算不因随后到期或撤销而转扣余额。
- WS沿用原生协议规则；包号额外检查仅为帧/轮次执行时的账号归属与有效期。

## 移除的独立规则

包号不再设置并发、RPM、每日次数、请求体字节上限、生图开关、HTTP入口白名单、WS帧类型白名单或JSON递归深度上限。准入中间件不再读取、解析或重置请求体。管理员“使用限制”表单及 GET/PUT billing-policy 接口已删除。

这些行为仍受Nginx及sub2api通用的请求体大小、用户/账号并发、用户/分组RPM、模型和生图权限、接口开关、协议校验、Key状态/到期/金额限额等约束。移除包号白名单不代表所有模型、账号或部署都支持所有接口。

Key金额计量恢复上游 ActualCost（含原生倍率）口径，不再强制按包号原始参考价 TotalCost 累计。免扣指客户余额/订阅不扣，不能解释为关闭管理员配置的原生Key限额；已有Key累计用量不清零。

账号类型、标准专属分组、无混用账号/影子账号/备用路由等既有结构校验仍用于维持归属隔离。本轮不扩展支持的账号平台或类型。

## 数据兼容

- 不修改已执行迁移243，不删除旧表、策略值或计数。
- custom_dedicated_billing_policies 与 custom_dedicated_request_counters 不再被运行时代码读写；旧配置不影响新请求。
- custom_dedicated_request_leases 保留作为免扣结算凭证表，兼容既有账本外键。新记录的 accepted_at、expires_at、finished_at 同时赋值，不占活动并发，没有续期任务和续期失败取消请求。
- 凭证仍在事务中验证归属/有效期后签发；账本继续验证该凭证的用户、Key、组、账号身份。数据库故障不会被当成免费资格放行。
- 更新前后端须同版；旧前端的策略接口调用会失效。回退旧代码会重新启用历史策略，不能把旧值仍存在误判为新代码仍限流。
