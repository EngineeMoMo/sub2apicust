## 管理入口

管理员进入「分组管理」，在指定分组的操作栏选择「开放规则」。简单运行模式不提供此功能。

每个分组可独立设置以下规则：

| 配置 | 含义 |
| --- | --- |
| 月净充值门槛 | 当前北京时间自然月的有效在线余额充值本金达到指定值 |
| 账户余额门槛 | 当前账户余额达到指定值 |
| 设置分组到期时间 | 为整个分组设置绝对到期时间，时区为北京时间 UTC+8 |
| 到期后使用的分组 | 原分组到期后，已有 Key 的新请求自动使用此分组 |
| 分时福利倍率 | 按指定日期设置最多32个不重叠时段，到点自动采用对应分组基础倍率 |

两个金额门槛各自独立开关，同时开启时必须同时满足；全部关闭且不设置到期时间时，沿用原有规则。达到门槛不会授予专属分组授权或订阅，原有权限条件仍然适用。

金额单位为 **USD 账户额度**，与用户账户余额单位一致。月净充值按充值订单入账额度减去赠送额度统计，不直接累计不同币种的付款金额，也不把手续费计入本金。兑换码、管理员加余额、活动赠送和订阅购买不计入月充值。

## 退款后的资格

选择分组不会永久解锁权限。分组列表、创建／修改 Key 绑定以及实际新请求都执行资格判断，正常请求读取独立资格缓存；普通认证缓存中的旧余额不会作为金额门槛依据。

- 已完成的在线余额充值计入其付款时间所在的北京时间自然月。
- 部分退款按订单已退比例扣除本金，赠送部分不算有效本金。
- 全额退款不计入。退款申请、退款中、待确认和退款失败未恢复完成态的订单暂不计入。
- 退款被拒绝或回滚、订单恢复 `COMPLETED` 后，按已完成充值计算；残留的申请金额不当作已成功退款。
- 退款后月净充值或余额低于任一已开启门槛，原先已绑定该组的 Key 在后续请求中也会被拒绝，不仅是在界面隐藏分组。

这里保留原有退款功能，通过重新计算资格阻止「先充值达标、选组后退款仍可使用」。站外退款或退款网关未同步到本站的变化，须先由现有订单流程正确入账，本功能不能凭空识别。

## 到期切换

开启到期设置必须同时选择目标分组。到期时刻包含边界，即当前时间大于或等于到期时间就使用目标。原分组从可选分组及模型广场隐藏，已有 Key 无需重新生成或手动改绑。

到期切换只改变单次请求中的有效分组，数据库中的原始 Key 绑定不作批量改写；请求路由、分组上下文、订阅验证、倍率与账单均使用有效目标分组。到期后不再要求原分组的金额门槛，但会要求目标分组的现有权限和开放门槛。

目标必须与原分组同平台、处于启用状态，并有可用账号支持原请求模型。专属目标需要用户已有授权，订阅目标需要有效订阅。目标删除、停用、权限不足或未达自身门槛时明确拒绝，不自动选择其他高权限分组。切换链不能循环，长度最多 32 个分组。

已在上游处理的流式请求不被中断。Responses WebSocket 每轮请求重新校验资格；原连接到期后需要重连重选上游，服务端返回可重试关闭码，重连自动使用到期后分组，无需用户手工改 Key。不能保证所有客户端都会自动重连。

到期设置与金额门槛独立：在到期之前因退款、余额下降或月初重算失去门槛资格时会拒绝使用原分组，不提前触发到期后路由。

## 升级与回归

### 请求路径缓存

规则、用户资格元数据、分组和月净充值使用独立进程缓存，不写入原 API Key 认证缓存。缓存有效期最多30秒，月充值在北京时间月初强制跨月；相同键的并发未命中合并一次回源。缓存最多4096项，达到上限清空后按需回源。未设置规则的请求只读取规则缓存，不汇总订单；仅开启余额门槛也不汇总月充值。

257迁移同时安装事务通知触发器。充值／退款订单变化在事务提交后通知所有应用实例失效对应用户的月净充值缓存；用户余额变化直接更新已缓存的资格余额，不触发充值聚合。用户权限、授权关系、分组状态、订阅有效期及规则变化分别失效关联缓存。订阅仅更新消费计数时不发资格通知，回滚事务不会广播变更。

每个应用实例增加一个 PostgreSQL LISTEN 连接，每秒心跳；连接断开或健康租约超过3秒时停止使用缓存，清空旧值并回源校验。重连后重新加载；回源失败拒绝请求，不用旧资格放行。失效通知与回源并发时通过加载令牌阻止旧值写回。通知异步传递，不能承诺提交后的下一条并发请求绝对零延迟；30秒TTL提供额外兜底。此缓存独立于现有计费余额缓存，避免修改账单预占或混用认证旧余额。

### 不定期福利时段

在同一「开放规则」弹窗开启「分时福利倍率」，为每一段选择北京时间的日期、开始时间、结束时间和倍率。这是一次性活动，不会每日循环；各段按 `[开始,结束)` 生效，可独立关闭并保留配置。时段间隙和最后一段结束后恢复分组原基础倍率；如需活动结束后换组，同时设置分组到期和兜底分组。

「填入三段福利示例」预填所选日期的00:00至18:00为0.1、18:00至20:30为0.15、20:30至23:00为0.1，并预填23:00到期；管理员仍须选择兜底分组，可编辑第一段开始时间。此按钮只修改待保存表单，不直接开启线上活动。

倍率替换分组基础倍率，和手动修改分组倍率的口径相同。已有用户专属倍率仍优先，高峰因子、独立图片倍率、渠道倍率及模型价格仍按原规则执行。可选分组与模型广场展示当前活动基础倍率；普通及Google API请求按请求开始时有效分组快照计费，跨时段完成的请求不追改基础倍率。批量生图提交时固定活动倍率到任务快照；Responses WebSocket 遇到分组或基础倍率变化须重连，重连自动应用新配置，无需修改Key。
