# 注册 IP 唯一限制（2026-10-22）

本功能默认开启。入口：管理员 → 系统设置 → 安全 → 注册设置 →「同一 IP 仅注册一个账号」。保存其他设置或使用旧版表单省略该字段时，保留当前值。设置键为 `registration_ip_limit_enabled`。

## 实际规则

- 邮箱注册、第三方首次自动建号、第三方补全邮箱／确认建号共用用户仓储事务。已存在账号的登录、绑定身份与管理员手动建号不占新注册名额。
- 注册 IP 来自 Gin 的可信代理链（`server.trusted_proxies`），忽略不可信客户端自行提交的 `X-Forwarded-For`／`X-Real-IP`。不使用旧版“直接信任转发头”兼容开关作为来源。
- 新迁移 `260_custom_registration_ips.sql` 保存来源，IP 唯一键与建号同事务提交；第二次建号返回 HTTP 403、reason=`REGISTRATION_IP_LIMIT`，提示登录已有账号或联系管理员。多进程共享同一数据库唯一约束。
- IPv4 与其 IPv4-mapped IPv6 形式归一化，IPv6 不同文本写法归一化；按完整地址限制，不扩大到整个 IPv6 网段。
- 数据库／来源不可核验时返回 HTTP 503、reason=`REGISTRATION_IP_UNAVAILABLE`，不放行注册。原始数据库原因保留在服务端错误链，不输出给访客。
- 普通删号、封号、重启、清 Cookie 都不恢复名额；无自动过期。建号事务回滚不占额。第三方暂存账号失败且补偿删除成功时，同一删除事务释放属于该账号的名额；不能释放其他账号占用的来源。
- 关闭开关允许同 IP 多次注册，但仍记录可解析的来源；重新开启后已记录来源继续受限。管理员可为共享网络用户手动建号，无需全站临时关闭防护。
- 只记录部署后的新注册，不猜测或回填历史账号 IP，不用最后登录 IP 冒充注册 IP。

## MAC 与防刷边界

普通网页没有读取访客真实网卡 MAC 的浏览器接口；客户端自行提交 MAC、随机设备 ID、Cookie 或浏览器指纹都不能当作可信 MAC。本次没有伪装实现 MAC 限制，也不新增设备指纹收集。

同一公司、家庭、学校或运营商共享公网 IP 的用户会共用一个名额。注册者更换公网 IPv4／IPv6 地址仍可能绕过，因此本功能不能保证完全阻止注册机。现有验证码、邮箱验证、邀请码、速率限制与认证 IP 黑名单继续生效。

## 发布前配置与验收

1. 本轮源码尚未发布。提交后核验同 SHA 的 CI（unit／integration、`go build -tags embed`）、安全扫描、GHCR，先备份数据库，再由用户手动更新前后端同版镜像；旧标签不包含此功能。
2. 反向代理部署先核实直接连接应用的代理源 IP 和转发头清洗方式，在私有配置 `server.trusted_proxies` 或容器环境 `SERVER_TRUSTED_PROXIES` 中仅填写实际可信代理地址／CIDR。不信任全网地址，不在仓库提交真实私有配置。具体解析和环境变量证据：`backend/internal/server/http.go`、`backend/internal/config/config.go`。
3. 未配置可信代理时，来源是 TCP 对端；Docker／反代后可能所有访客都是同一代理 IP。不能仅打开旧版“信任转发 IP”开关就当此限制已正确配置。上线前核实实际来源，必要时先在后台关闭本限制完成配置，再启用。
4. 隔离测试账号验证：同 IP 首次成功、不同邮箱第二次被拒绝且无孤儿账号；不同 IP 成功；已有账号从相同 IP 正常登录；共享网络由管理员建号。验证直接伪造转发头不能绕过、可信代理正确转发、第三方首次建号也受限。
5. 验证关闭／开启与设置回显、删号后继续受限、邀请码事务失败可重试、第三方补偿回滚可以重试。生产实际代理链、PostgreSQL 并发与真实 OAuth 全流程须独立验收，不能以 SQLite 测试或本地编译代替。
