前端支付操作复用现有验证码对话框：授权不足时提示输入 TOTP，通过后仅重试原请求一次；取消不继续原请求、不弹业务失败提示。未绑定或使用机器凭证时提示原因；验证码通过后的业务错误正常返回，不无限重试。

## 管理员启用顺序

绑定前须确认生产部署已持久配置 `TOTP_ENCRYPTION_KEY`：沿用已有固定值，不要在升级时重新生成或替换。若此前未配置且尚无人绑定，在服务器生成 `openssl rand -hex 32`，写入部署目录私有 `.env`，确认 Compose 将其传入容器后重建应用，再进行绑定；不要提交密钥。源码 `backend/internal/config/config.go` 在缺少配置时每次启动自动生成随机加密密钥，重启后无法解密此前绑定资料，因此不能在临时密钥下完成正式绑定。如果已有人绑定且不清楚原密钥，先恢复原配置，不直接换新值。

1. 发布前备份数据库、配置、数据目录，记录现有镜像；本轮尚无已核验的新发布标签，不能套用旧标签。后续正式发布须检查该业务 SHA 的 CI、安全扫描与构建。
2. 更新前后端同版。此前注册 IP 限额的迁移 260、订阅兑换迁移 259 属其他已授权工作，本次安全补修没有新增迁移，仍需按对应文档一并核实升级范围。
3. 管理员进入个人资料绑定验证器并保存恢复资料。新版管理员绑定不依赖普通用户的全站 TOTP 开关。用独立浏览器验证密码登录确实要求 TOTP，保留可用的原管理会话直至验证完成。
4. 每位需要执行敏感操作的管理员完成绑定后，在系统设置→安全打开“敏感操作二次验证”。开启前已有本人绑定校验；不自动强迫普通用户绑定。
5. 核验退款/通道修改/人工记账/主设置保存出现验证码提示，取消无业务动作、正确验证后执行一次；没有授权或使用管理员 API Key 的写请求应被拒绝。使用隔离账号和测试通道，不拿真实退款作无确认测试。

本地自动回归已覆盖上述登录、门控、取消、重试与故障分支；实际管理员手机扫码和生产会话仍需本人完成。未启用 `step_up_enabled` 时，支付写操作保持原配置下的行为，不能宣称二次验证已经生效。

## HTTPS 与边缘限流部署

模板：`deploy/nginx-security.conf.example`。这是待按现场合并的完整 HTTP 配置示例，不直接覆盖已有站点文件。`limit_req_zone` 和 `map` 放在 Nginx `http` 上下文；不要重复嵌套 `http` 或重复定义现有同名区域。

1. 将所有 `example.com` 换成实际公网域名，证书路径换成现有有效证书；上游 `127.0.0.1:8080` 换成实际服务地址。本例固定跳转到已配置域名，不能改为信任任意请求 Host。保留现有 ACME 续签、其他业务 location 和安全规则。
2. 配置应用 `server.trusted_proxies` / `SERVER_TRUSTED_PROXIES` 为真正直接连接应用的代理 IP/CIDR。Docker 场景需现场确认连接来源，不能盲填 127.0.0.1 或全网段。代理覆写 `X-Forwarded-For` 和 `X-Forwarded-Proto`。
3. 如前面还有 CDN，先正确配置并校验可信 real-IP 链；不信任公网任意转发头，源站入口应按实际架构限制。应用 IP 注册/查询预算均依赖该链。
4. 在生产保存旧站点配置，执行 `nginx -t`；成功后再按原部署方式 reload。当前本机无可用 nginx，本轮没有执行或声称通过现场 `nginx -t`，也没有修改生产。
5. 从外网验证以下响应，再用实际正常查询频率验证限流。HSTS 缓存会要求浏览器持续使用有效 HTTPS；回滚配置不能立即清除所有客户端缓存。

```text
curl -I http://实际域名/login
# 预期：308，Location 为实际域名的 HTTPS /login。
curl -I https://实际域名/login
# 预期：Strict-Transport-Security: max-age=31536000。
curl -I https://实际域名/api/v1/user/profile
# 预期：匿名 401，仍含 HSTS。
```

模板只对公开订单查询加严格边缘限流，webhook 维持原支付验签流程。不要对支付回调套用普通查询预算。普通代理保留 WebSocket Upgrade 与流式输出；合并时保留原长连接、上传和请求体大小策略。

## 防 VPN 注册的范围

没有自动启用邀请码或改变注册赠额，不新增 MAC/浏览器指纹。IP 限额无法保证轮换公网 IP 时一人一号。是否启用受控一次性邀请码、调整新账号权益，仍应结合实际注册和消耗日志；本轮不把缺少生产日志的推测写成已发生攻击。
