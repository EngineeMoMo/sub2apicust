## 操作与口径

后台「订单管理 → 订阅套餐 → 创建／编辑」新增「售卖总限额（份）」。

- `-1`：不限量，升级后的既有套餐及新建默认均如此。
- `0`：停止新增售卖，已有预占订单仍可正常付款。
- 正整数：该套餐累计可售总份数，包含已售及待付预占。例如已占用 20，想再卖 10，填 30。
- 限额可以低于已占用份数，此时剩余为 0，不撤销已有订单或订阅。修改名称、上下架等时遗漏库存字段会保留原限额。
- 每次新购或续费占一份；不同套餐独立。不按用户人数、并发连接数或当前有效订阅数计数。
- 用户卡片与游客目录显示剩余份数；售罄保留卡片、禁用购买。旧页面或直接请求仍受数据库校验。

## 库存与付款

### 管理员及其他非购买分配（同轮补充）

- 管理员单次／批量分配新增「库存套餐」选择，显示该分组各套餐剩余量。实际新增或过期重开扣一份；有效订阅的幂等复用不再扣。下架套餐仍可由管理员分配，但有限库存为 0 时不可分配。
- 管理员正向调整有效期扣一份；单次可选套餐，批量调整按每条订阅的最近库存归属扣减。缩短、撤销、恢复同一份既有权益不补货，也不另扣。库存不足时本次订阅写入与库存事务一起回滚；批量按用户返回成功／失败，不回滚已成功用户。
- 兑换码、注册默认赠送、后台创建用户默认赠送均复用受库存约束的分配服务。没有指定套餐时先使用此订阅的库存归属，否则仅分组唯一套餐可自动关联；无套餐／多套餐无法确定时拒绝分配。默认赠送失败沿用原调用方日志处理，不回滚用户注册；兑换码失败沿用原事务回滚。
- 每次实际新授予／续期扣一份，与天数无关。不限量套餐也累计占用，日后设置有限总额时包含这些分配。已付款订单履约只登记归属，不重复扣，也不依赖随后可能删除／调组的现售配置。
- 「我的订阅」按分组显示可售套餐的库存；全部售罄则禁用续订。加载中、接口失败或没有可售套餐时不允许发起续订，已有订阅权益继续显示。购买页和服务端再次校验实时库存。

新增 `246_custom_subscription_manual_stock.sql` 与独立库存归属账本。历史人工订阅仅在“分组唯一套餐且该用户／分组没有已付订阅订单”时回填一次。**旧系统没有每次人工分配对应的套餐记录，不能还原多套餐、混合来源、已删除记录或历史多次续期的确切总量**，须上线前人工核对，不把回填数称为完整历史销量。以下只读 SQL 可列出没有库存归属的历史订阅：

```sql
SELECT s.id, s.user_id, s.group_id, s.status, s.expires_at
FROM user_subscriptions s
WHERE NOT EXISTS (
  SELECT 1 FROM custom_subscription_stock_allocations a WHERE a.subscription_id=s.id
)
ORDER BY s.group_id,s.id;
```

该列表也可能包括已有购买订单覆盖的订阅，不能直接批量补扣。首次设置限额时核对历史占用与期望新增量；需要保守预留历史未计入份额时，从计划总限额中扣掉预留份额，并另行保存核对记录。后续新增／续期由统一事务记账。

### 购买订单

订单创建时预占，与订单同事务提交。取消、过期或网关创建失败的**未付款**订单释放；释放依赖后端状态实际更新，不以浏览器倒计时或关闭页面为依据。

已付款、履约失败后重试、完成、退款、订阅到期均不自动补货。后台提高总限额补货。迁移回填当前数据库仍保留的历史订单；升级前已经删除的订单无法凭空还原。升级后删除已付订单不会自动补库存。

数据库触发器通过同一套餐行的原子条件更新裁决并发，重复状态更新不重复占用或释放。数据库错误不会被当作库存充足。`stock_used` 不接收管理 API 的客户端赋值。

取消／过期后迟到的真实付款，须重新占用库存；不足时不自动开通，并写 `PAYMENT_STOCK_UNAVAILABLE` 支付审计（订单号、交易号、金额）。管理员必须向商户核实到账：仍在原订单恢复期限内可补货并重试有效通知，否则通过商户渠道人工处理退款。**没有新增自动退款或自动续期承诺**。原过期订单的付款恢复宽限期保持，超过宽限期走既有 `PAYMENT_AFTER_EXPIRY` 审计路径。不要仅以本地 CANCELLED／EXPIRED 状态判断商户一定未收款，也不要直接改库强制履约。

网关失败写回改为只更新仍 PENDING 的订单，避免覆盖提前到达的付款回调。未确认到账的 FAILED 订阅不能由管理员直接重试开通；经过验签、金额核验的有效回调可将其转 PAID 并重新取得库存。余额订单恢复规则保持。
