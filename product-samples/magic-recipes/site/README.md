# 魔法配方 · 本地交互原型

这是可独立使用、也可在魔法 API 控制台内打开的静态内容工具，支持整理提示词、手动接入自己的兼容模型接口，以及选择本人已有魔法 API 连接。母品牌与Logo不变；最新要求为无偏好默认浅色，内嵌时跟随 API 主题。SynaRoute不变。

## 模型接入操作

### 登录魔法 API 选择配置

1. 打开“模型设置”，选择文字或生图用途，点击“登录魔法 API 并选择配置”。
2. 在新窗口使用原站登录流程；已有会话时直接进入选择页。不在配方页输入密码，不把原站登录令牌带回配方。
3. 选择自己的已有密钥与绑定分组，再从该密钥的模型目录选择模型。文字可选择 Chat Completions／Responses；生图需选择真正支持 Images API 的模型，目录不代表能力已验证。
4. 核对显示的接收页面来源，明确点击“将所选配置用于魔法配方”。原站只发送所选 API Key、API 地址、模型和接口格式；配方接收并确认后才显示成功。
5. 回到配方检查材料与提示词，再手动运行。登录、选择和导入本身不调用生成模型；目录查询会请求所选密钥的 GET /models。

当前源码两端已接线，但没有发布到线上。本站入口 /connect/recipes 复用 requiresAuth 路由保护与原登录的站内 redirect。独立部署必须在魔法 API 构建环境明确配置 VITE_MAGIC_RECIPES_ORIGIN 为配方完整来源（协议＋域名＋端口，不含路径）；默认生产只允许同源，本机站允许本机4178预览来源。该变量属于站点构建配置，不提交实际.env文件。两端更新后仍须核对 API 的 CORS、模型权限与浏览器窗口隔离策略。

本机测试把“魔法 API 网站”改为 http://127.0.0.1:4175（源码Vite预览），4178保持运行。当前8080镜像和线上没有新增选择页，不能用旧镜像验收。线上登录入口只允许 https://ai.mofamilys.com；其他兼容服务仍走手动连接。

回传严格验证来源、原窗口、32字节随机nonce、连接用途和五分钟有效期，一次性接受；不使用通配targetOrigin。URL只有页面来源、nonce与用途，没有密钥、账号凭据或输入材料。拒绝未获准来源，不自动创建或改绑密钥；只列出启用、有效分组、未到期及未耗尽配额的本人密钥，生图明确禁用的分组被排除。取消、窗口关闭／隔离和过期后可重试；清除配方连接不会注销原站账号。不要为了此功能关闭浏览器安全保护。

### 手动填写兼容接口

1. 打开顶部“模型设置”，选择文字或生图；填写 API 根地址（例如你自己的 HTTPS 域名/v1）、API Key、服务商提供的准确模型名。
2. 文字选择 Chat Completions 或 Responses；生图使用 Images API，可选填服务支持的尺寸。根域名自动补 /v1，已有路径按原样保留，也可填写对应完整端点。
3. 点击“应用当前连接”，再收起设置。这里只校验配置，不发送验证请求，不扣费。
4. 填材料并整理提示词，检查后点击“用我的模型运行”或“用我的模型生图”。文字可以继续追问；每次运行和追问由自己的服务计费。视频请复制到目标视频工具。

地址、密钥、模型、材料与对话仅存本页内存，刷新全部清除；没有本地存储或后端代管密钥。密钥只在 Authorization 请求头发送给配置接口，不放到 URL 或正文。浏览器不携带 Cookie、不跟随 API 重定向、不自动重试；结果不作为 HTML 或命令执行。

远程只支持 HTTPS，本机 localhost／127.0.0.1／[::1] 支持 HTTP。接口需允许页面来源（本机预览为 http://127.0.0.1:4178）的 CORS，包括 POST、Authorization、Content-Type。连接失败不等于密钥错误，需分别排查地址、网络、TLS和跨域；不绕过浏览器限制。当前未适配原生 Anthropic Messages、异步生图或视频任务接口。

文字等待上限 120 秒，生图 180 秒；停止等待仅终止浏览器请求，不能保证服务端任务取消或不计费。修改材料、切换配方、重新整理或更改当前连接会清除旧模型对话并停止等待；同页配方材料仍按原规则保留。答案与图片没有本地自动保存。

实现格式参考官方[文字接口迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)与[Images API](https://developers.openai.com/api/reference/cli/resources/images)，实际兼容性以用户服务为准。
